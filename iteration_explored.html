23 Overview

This document pulls out elements from R for DS Chapter 21, which is on ways of doing iteration. And then it jumps to the map() function and list columns extensively used in Chapter 25. It is all within the tidyverse:

library( tidyverse )

24 The map() function (R for DS 21.5)

The core idea of map is to take a list and call a function on each thing on that list. This list could be a list of lists (i.e. a dataframe), which can be very important, because then you can call a function on each column in your dataframe.

Generally what map gives back is another list, with each element being what we got back from the function from each call. If your first list has named items, your result will have those names as well. This can be quite useful.

To illustrate we make a silly list with a list inside it, and then call map():

lst = list( 1, B=3, inner_list = c(10, 20, 30) )
lst
[[1]]
[1] 1

$B
[1] 3

$inner_list
[1] 10 20 30
map( lst, mean )
[[1]]
[1] 1

$B
[1] 3

$inner_list
[1] 20

See? We got the mean out of each element in our list.

By adding _dbl or similar, we can explicitly tell map() to turn this list into a vector of some type:

map_dbl( lst, mean )
                    B inner_list 
         1          3         20

We also have map_int, map_chr, map_lgl, and map_df. Be warned, if you call one of these and the things you get back are the wrong type, you get an error:

map_df( lst, mean )
Error in `dplyr::bind_rows()`:
! Argument 1 must be a data frame or a named atomic vector.

24.1 Making data frames

The map_df() is especially important. But you need something that gives back a dataframe for it to work! This dataframe can be a 1 row dataframe, however. For example:

my.func = function( numbers ) {
    data.frame( mean=mean(numbers), sd=sd(numbers) )
}
map_df( lst, my.func )
  mean sd
1    1 NA
2    3 NA
3   20 10

24.2 The unlist() function

A useful function is unlist which takes a bunch of lists and just smashes it all together into one vector

unlist( lst )
                      B inner_list1 inner_list2 inner_list3 
          1           3          10          20          30

It even keeps the names, if there are any!

24.3 Extra arguments to map

If your function takes extra stuff, then you can pass it along like so:

log( 10, base=3 )
[1] 2.095903
map( lst, log, base=3 )
[[1]]
[1] 0

$B
[1] 1

$inner_list
[1] 2.095903 2.726833 3.095903

25 Banging on Dataframes

If you have a dataframe that is a bunch of smaller dataframes, you can get a list of the smaller dataframes via split(). This will make a new dataframe with the rows corresponding to each unique value of a passed variable:

df = data.frame( A=1:6, B=c("A","A","A","B","B","C") )
df.list = split( df, df$B )
df.list
$A
  A B
1 1 A
2 2 A
3 3 A

$B
  A B
4 4 B
5 5 B

$C
  A B
6 6 C
class( df.list )
[1] "list"
map_dbl( df.list, nrow )
A B C 
3 2 1

See R for DS 25.5.1

25.1 Chaining map

You can chain maps together. Say we are going to fit a linear model for each group of a dataframe defined by different values of a categorical variable. For example, lets divide the famous “iris data” into groups by species, and then fit a linear model for each group, and then get the R squared from that model.

Before we dive into this, we need to note that you can use “.” as a pronoun for “the thing we are working on.” So, for example, the following two lines are equivilent:

iris.list = split( iris, iris$Species )
iris.list = iris %>% split( .$Species )

The “.” is what is “coming down the pipe.”

Now we call lm() on each part by writing a function to analyze our dataframe:

my.func = function( my.df ) {
    lm(  Sepal.Length ~ Sepal.Width, data=my.df )
}

mods = iris.list %>% map( my.func )

Our mods is a list of results. Here is the first result (a linear regression output):

mods[[1]]

Call:
lm(formula = Sepal.Length ~ Sepal.Width, data = my.df)

Coefficients:
(Intercept)  Sepal.Width  
     2.6390       0.6905

The above can be bundled as follows

mods = iris %>% split( .$Species ) %>% map( my.func )

But writing the wrapper function for lm is annoying. We can tell our map that we are “writing a function on the fly” with an abuse of the “~” notation:

mods = iris %>% split( .$Species ) %>% 
    map( ~lm( Sepal.Length ~ Sepal.Width, data=. ) )

Here we are saying, inside the map, that we want to run the lm() function, and that the stuff we got from the map should be the data argument (data = .).

Finally, we map the above again to summary to calculate our R squared, and then we extract it:

names( summary( mods[[1]] ) )
 [1] "call"          "terms"         "residuals"     "coefficients" 
 [5] "aliased"       "sigma"         "df"            "r.squared"    
 [9] "adj.r.squared" "fstatistic"    "cov.unscaled" 
rs = iris %>% split( .$Species ) %>% 
    map( ~lm( Sepal.Length ~ Sepal.Width, data=. ) ) %>%
    map( summary ) %>%
    map_dbl( ~.$r.squared )
rs
    setosa versicolor  virginica 
 0.5513756  0.2765821  0.2090573

The ~.$r.squared line is a bit weird. We are taking our pronoun, and grabbing the “r.squared” variable from inside it (if there is no such value inside it we will get NA). This is a common activity, and thus the tidyverse provides a shortcut: just put in the name as a string:

rs = iris %>% split( .$Species ) %>% 
    map( ~lm( Sepal.Length ~ Sepal.Width, data=. ) ) %>%
    map( summary ) %>%
    map_dbl( "r.squared" )
rs
    setosa versicolor  virginica 
 0.5513756  0.2765821  0.2090573

25.2 Dataframes are lists of the columns

Let’s calculate the unique number of values in each column of iris:

analyze_column = function( col ) {
    length( unique( col ) )
}
map_dbl( iris, analyze_column )
Sepal.Length  Sepal.Width Petal.Length  Petal.Width      Species 
          35           23           43           22            3

Or, by map chaining:

iris %>% map( unique ) %>% map_dbl( length )
Sepal.Length  Sepal.Width Petal.Length  Petal.Width      Species 
          35           23           43           22            3

25.3 The transpose() function

We can do some funky list manipulation. Say our map gives us back a list of pairs (note cool select_if() to grab only numeric columns):

my.func = function( col ) {
    c( mean=mean(col), sd=sd(col) )
}
res <- iris %>% select_if( is.numeric ) %>% map( my.func )
res
$Sepal.Length
     mean        sd 
5.8433333 0.8280661 

$Sepal.Width
     mean        sd 
3.0573333 0.4358663 

$Petal.Length
    mean       sd 
3.758000 1.765298 

$Petal.Width
     mean        sd 
1.1993333 0.7622377

But this is hard to use. transpose() to the rescue!

res2 <- transpose( res )
names(res2)
[1] "mean" "sd"  
res2$mean
$Sepal.Length
[1] 5.843333

$Sepal.Width
[1] 3.057333

$Petal.Length
[1] 3.758

$Petal.Width
[1] 1.199333

We now have two lists, one for the means, one for the sds.

See R for DS 21.6 for more on this.

26 List columns and notes on R for DS 25 (25.2)

Chapter 25, while nominally about modeling, actually shows a lot of useful code for complex data wrangling. In particular it talks about list columns, which are ways of storing data in chunks and manipulating the data chunk-by-chunk. This connects heavily with the map concepts above.

26.1 List columns

A “list column” is a column of your dataframe where each entry in the column can be anything you want, including a list or entire dataframe. For example, we can make some on the fly using enframe() (See R for DS 25.4.4)

x <- list( a=c("a","b"),
  b = 3:7, 
  c = iris
) 

df <- enframe(x)
df
# A tibble: 3 × 2
  name  value         
  <chr> <list>        
1 a     <chr [2]>     
2 b     <int [5]>     
3 c     <df [150 × 5]>

There are several ways to make list columns to be aware of:

  • Using nest()
  • Using mutate() where your call gives a list back (e.g., due to map())
  • Using summarise() with a function that gives back multiple results (such as quantile()).

26.2 nest() and unnest()

In particular, you can group a dataframe by something, and then nest it to make a small dataframe with each row corresponding to a single dataframe slice of your original data

dfs <- iris %>% group_by( Species ) %>% nest()
dfs
# A tibble: 3 × 2
# Groups:   Species [3]
  Species    data             
  <fct>      <list>           
1 setosa     <tibble [50 × 4]>
2 versicolor <tibble [50 × 4]>
3 virginica  <tibble [50 × 4]>
# look, our 2nd value in our dataframe's data variable is a
# dataframe!
head( dfs$data[[2]], 3 )
# A tibble: 3 × 4
  Sepal.Length Sepal.Width Petal.Length Petal.Width
         <dbl>       <dbl>        <dbl>       <dbl>
1          7           3.2          4.7         1.4
2          6.4         3.2          4.5         1.5
3          6.9         3.1          4.9         1.5

Now you can use map to make new columns!

26.3 Using summarise()

We can call summarise() with functions that give multiple things. We need to wrap the response in a list.

ir2 <- iris %>% group_by( Species ) %>% summarise( probs = list( c( 0, 25, 50, 75, 100 ) ), 
                                            quants = list( quantile( Sepal.Length )) )
ir2
# A tibble: 3 × 3
  Species    probs     quants   
  <fct>      <list>    <list>   
1 setosa     <dbl [5]> <dbl [5]>
2 versicolor <dbl [5]> <dbl [5]>
3 virginica  <dbl [5]> <dbl [5]>

Note the wrapping of everything in the list. Now each row has a list of the probabilities and a list of the results. We can get back a long frame with unnest():
